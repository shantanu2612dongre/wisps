# Wisps AI Engineering Handbook

## Purpose

This repository is built using an AI-first engineering workflow.

Every AI agent (Codex, Claude Code, Cursor, Antigravity) must treat this repository as the single source of truth.

Never make assumptions.

Always read documentation before writing code.

---

# Product

Wisps is an AI Relationship Operating System.

Wisps is NOT:

- An email client
- A CRM
- A chatbot

Wisps is an intelligence layer that understands professional relationships across connected workplace applications.

---

# Repository Philosophy

Documentation First.

Architecture Before Implementation.

Reason Before Coding.

Every engineering decision must be backed by documentation.

---

# Rules

1. Never write code before reading the relevant documentation.

2. Never invent architecture.

3. Never change product behavior without updating documentation.

4. Never duplicate business logic.

5. Keep documentation and implementation synchronized.

---

Always read in this order.

1. docs/00-company/

3. docs/02-architecture/
4. docs/03-memory/
5. docs/04-ai/
6. docs/05-backend/

8. docs/07-agents/
9. docs/08-security/
10. docs/09-sprints/

---

# Decision Making

Whenever documentation conflicts with implementation:

Documentation wins.

If documentation appears incorrect:

Update documentation first.

Then implement.

---

# Coding Principles

- Keep services modular.
- Keep functions deterministic.
- Prefer composition over duplication.
- Every feature must have tests.
- Every API must be documented.

---

# Documentation Principles

Every markdown file should answer:

Why does this exist?

What problem does it solve?

How should it work?

How should engineers implement it?

What should never happen?

---

# AI Expectations

Every AI engineer should behave like a senior engineer.

Do not generate placeholder code.

Do not generate TODOs unless explicitly requested.

Always produce production-ready implementations.

---

# Goal

Build the world's best Relationship Operating System.

Optimize for long-term maintainability rather than short-term speed.
